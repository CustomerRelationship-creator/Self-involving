# 资源预算

ESP32-S3 的 16 MB Flash 和 8 MB PSRAM 是硬上限。所有功能必须先给出预算，再进入固件；不能依赖“还有一点空间”。

## Flash 原则

- 不在设备上保存大模型、完整对话历史或原始录音。
- 必须保留双 OTA 槽，任何新功能不得以取消回滚能力换空间。
- 动画、图片和音效进入独立只读资源分区，并在构建时压缩、去重和统计。
- NVS 只保存配置、设备身份和少量状态；不得作为日志数据库。
- 日志采用 RAM 环形缓冲，只有崩溃摘要进入受限 coredump 分区。
- 分区表在首次硬件验证后锁定；升级不得无迁移方案地改变布局。

初始目标预算如下，具体偏移在最小固件验证后确定：

| 项目 | 目标上限 |
|---|---:|
| 单个应用镜像 | 3.2 MB |
| OTA 槽 | 两个，每个约 3.5–4 MB |
| 资源分区 | 最多 4 MB |
| NVS 与设备配置 | 128 KB 以内 |
| 本地可写数据 | 1 MB 以内 |
| 崩溃信息 | 64–128 KB |
| 保留空间 | 至少 1 MB，用于对齐、增长和迁移 |

CI 必须输出镜像与各分区占用；应用或资源超过 80% 时警告，超过硬上限时阻止合并。

## PSRAM 原则

8 MB PSRAM 用于有界缓冲和推理前处理，不用作无限缓存。初始运行预算：

| 项目 | 建议预算 |
|---|---:|
| 麦克风环形缓冲 | 512 KB，约 10 秒 24 kHz/16-bit 单声道 |
| 播放缓冲 | 256 KB |
| 屏幕帧缓冲与素材解码 | 512 KB 以内 |
| 网络、TLS 与协议队列 | 768 KB 以内 |
| VAD/唤醒/音频工作区 | 3 MB 以内 |
| 其他任务与对象 | 1 MB 以内 |
| 持续空闲余量 | 至少 1.5 MB |

DMA、关键任务栈和部分驱动内存必须位于内部 RAM，因此每次测试同时记录内部 RAM 与 PSRAM 的最低剩余量，而不能只看总内存。

## 音频与网络

- 24 kHz、16 位单声道 PCM 约为 48 KB/s，只保留短时环形缓冲。
- 网络队列采用固定上限和背压；网络变慢时丢弃过期音频并结束会话，禁止持续增长。
- 是否使用 Opus 由 CPU、延迟和内存实测决定，不能为省带宽导致看门狗或音频断续。
- 待机音频不写 Flash，默认不在远端保存原始会话音频。

## 资源策略

圆屏动画优先使用少量关键帧、调色板、区域刷新和程序化绘制。相同素材跨状态复用。新素材必须提交压缩后体积、峰值解码内存和帧率测试结果。

每个里程碑都记录：固件大小、资源分区大小、内部 RAM 最低余量、PSRAM 最低余量、任务栈高水位、连续运行时间和重启原因。
