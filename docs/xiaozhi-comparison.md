# 与 xiaozhi-esp32 v2.4.2 的对比

比较基线固定为 [78/xiaozhi-esp32 v2.4.2](https://github.com/78/xiaozhi-esp32/tree/v2.4.2)，避免把不同版本的能力混在一起。小智已经是成熟、广覆盖的通用 AI 语音终端；Self-involving 的目标不是用更少代码宣称“全面超过”，而是为这一台身体换取更深的连续性、可解释性和实机调优。

## 小智值得保留的工程思想

根据其 [功能说明](https://github.com/78/xiaozhi-esp32/blob/v2.4.2/README_zh.md)、[音频架构](https://github.com/78/xiaozhi-esp32/blob/v2.4.2/main/audio/README.md) 与 [协议定义](https://github.com/78/xiaozhi-esp32/blob/v2.4.2/main/protocols/protocol.h)，以下方向已经被实机验证，原创固件不应无理由倒退：

- ESP-SR AFE 统一承担 WakeNet、VAD 与 AEC。
- 音频采集、Opus 编解码、网络发送和播放使用独立任务与有界队列。
- WebSocket 或 MQTT/UDP 承载控制事件和双向音频。
- 状态机、设备端 MCP 工具、OTA 双槽和资源分区。
- 服务器下行 24 kHz 音频，设备上行采用压缩语音帧。
- 通过板级抽象支持大量硬件和显示形式。

ESP-SR 官方 AFE 同时提供 [AEC、NS、VAD、AGC 与 WakeNet](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/README.html)，因此这些基础 DSP 优先使用官方实现并进行板级调参。

## 差异化方向

| 方面 | xiaozhi-esp32 v2.4.2 | Self-involving |
|---|---|---|
| 产品范围 | 通用框架，覆盖大量芯片、板卡与发布变体 | 只支持一个已知板型，允许对 ES8311、圆屏、内存和声学结构深度调优 |
| 身份 | 可配置的聊天机器人终端 | 一个持续存在的实体身份；会话、记忆、权限和身体状态属于同一实体 |
| 音频 | 成熟 AFE/Opus 流水线，默认 60 ms Opus 帧；2 秒、64 KB 唤醒缓存 | 目标 20 ms 帧以降低交互延迟；缓存、AEC、丢帧和回声路径全部可测量 |
| 状态 | 启动、配网、空闲、连接、聆听、说话、升级等 | 增加 THINKING、MUTED、DEGRADED_OFFLINE、RECOVERY 和权限确认；每个状态必须可见 |
| 协议 | 面向小智服务的 WebSocket/MQTT 协议，支持 MCP | 首版只保留 TLS WebSocket 和小型有版本协议；模型供应商通过远端适配器替换 |
| 工具 | ESP32 作为 MCP 服务器暴露设备工具 | 设备只接受枚举且可撤销的身体动作；复杂工具和权限账本留在认知服务 |
| 主动性 | 主要由服务端对话和命令驱动 | 支持受约束的主动提醒、注意事件和原因说明；所有外部动作可追溯、可取消 |
| 离线 | 本地唤醒和设备操作 | 增加明确的退化模式：静音、音量、诊断、配网和恢复不依赖服务器 |
| 显示 | 文本、表情、主题和丰富资源 | 圆屏优先显示注意力、意图、权限和真实系统状态，装饰动画服从资源预算 |
| 存储 | 16 MB 方案使用两个约 3.94 MB 应用槽和 8 MB assets 分区 | 资源目标最多 4 MB，换取本地可写区、诊断区和至少 1 MB Flash 迁移余量 |
| OTA | 支持升级和标记版本有效 | 新版本必须先完成音频、网络、资源和持续内存自检才确认；失败自动回滚 |
| 可维护性 | 跨大量硬件的条件编译与板级目录 | 单板静态配置、少量模块、严格内存预算和故障注入测试 |

小智的 [16 MB 分区表](https://github.com/78/xiaozhi-esp32/blob/v2.4.2/partitions/v2/16m.csv) 把剩余 8 MB 全部分配给 assets。我们的主要取舍是减少素材规模，换取诊断、迁移和长期演进空间。

## 真正的升级

升级不等于增加天气、日历或更多表情。真正的升级是：

1. 它知道自己此刻在听、推理、等待权限还是离线，并诚实显示。
2. 它能够延续与你的关系，而不是每次唤醒都变成一个新客服窗口。
3. 它有主动性，但每次主动行为都能说明触发原因并被立即停止。
4. 它把有限 Flash、PSRAM、网络和注意力当成预算，而不是无限资源。
5. 它能在远端服务失效时安全退化，而不是失去身体控制。
